# Trading-Nova V1 Product Gap Audit

**Reviewed main:** a281857a5d47ca6785e93d17f706c755ef1faab7  
**Contract source:** Section 21, LOCKED USER PRODUCT CONTRACT, in docs/TRADING-NOVA-MASTER-ROADMAP.md  
**Scope:** current user-facing website, HTTP routes, active API handlers, core market/order/risk/backtest/research/journal modules, tests, and the V1 external-evidence runbook.  
**Type:** static implementation audit. This is not a production certification, profitability claim, or independent runtime penetration test.

## Executive conclusion

Trading-Nova has a substantial and usefully safety-oriented paper-trading foundation: private access gating, a server-side deterministic Risk Gate, persistent/idempotent paper execution, market freshness/failure states, a responsive dashboard, a hash-chained journal, a market-data fallback/cache, a backtest engine, and focused tests are present.

However, having a module is not proof that the complete locked user feature is connected end-to-end. The most consequential product gap is **order-type semantics**: the API accepts MARKET, LIMIT, STOP_LOSS, and TAKE_PROFIT, but the persistent engine currently creates an immediate full-quantity fill at the current mark price and records fee 0; it does not preserve or execute the requested type or trigger prices. The order-type fields are also omitted from the risk-gate payload hash. This should be fixed before presenting these order types as supported.

The backtest engine has optional out-of-sample support, but the active HTTP backtest handler does not pass a walk-forward split, so that route's normal result has no out-of-sample run. The AI council exposes seven labeled roles, but several roles are heuristic proxies (the “News” role uses 24-hour price change; the “Fundamental” role uses quote volume; the “Sentiment” role uses volatility regime), not source-backed public research. The current route inventory contains no public-news or editable-watchlist endpoint.

**Overall: implementation foundation exists; the full locked V1 user contract is not yet complete.** Do not mark the release certified or infer expected profitability from the present code or green CI.

## Status and priority definitions

- **Implemented + tested:** an end-to-end code path and meaningful regression evidence exist for the stated bounded feature.
- **Partial:** some implementation exists, but user-visible behavior, integration, acceptance tests, or operational evidence is incomplete.
- **Missing:** the required user-facing behavior or active integration path was not found in the reviewed code.
- **External evidence required:** code or CI support cannot substitute for an environment-specific operational artifact.

P1 means fix before calling that feature release-ready; P2 means important next-stage completeness/quality work. Priorities do not imply that real-money trading is enabled. It remains OFF.

## Ranked next implementation queue

1. **P1 — Stop silent order-type coercion.** Implement MARKET/LIMIT/STOP_LOSS/TAKE_PROFIT as distinct paper-order states and trigger conditions, or temporarily reject/hide unsupported types. Bind order type and trigger fields into validation, idempotency intent, and Risk Gate artifact semantics. Add route-level tests for trigger/no-trigger, price crossing, replay, cancellation/restart, and no premature fill.
2. **P1 — Make paper accounting realistic and reconcilable.** Model fee, spread, and slippage separately; then add deterministic partial/cancel/reject/latency lifecycle support or mark those behaviors unsupported. Verify the same ledger feeds order history, portfolio positions, P&L, and restart recovery.
3. **P1 — Expose honest OOS/backtest behavior through the real route.** Add validated walk-forward input, non-null OOS when requested, sensitivity/benchmark outputs, and tests through /api/backtest and Strategy Lab rather than only testing the engine in isolation.
4. **P1 — Build a source-backed public research path.** News/sentiment/Internet Brain inputs need source URLs, provenance, timestamps, freshness/trust, and untrusted-text isolation. In the meantime clearly label momentum/volatility proxies and do not call them real news/sentiment.
5. **P1 — Connect the risk dimensions promised in the contract.** Demonstrate that any advertised correlation, volatility, and liquidity controls are computed from valid fresh inputs and enforced in the same deterministic order gate. Missing/invalid critical risk inputs must fail closed.
6. **P2 — Complete durable learning and strategy selection.** Expose thesis/outcome/loss-autopsy reports, align the strategy allowlist with implemented public strategies, and add user-editable/persisted watchlists and end-to-end challenger/shadow promotion flows.
7. **External gate — Keep V1 uncertified until actual artifacts exist.** Complete the external-evidence runbook with real environment, operator, timestamps, measured results, and redacted commands/logs. Do not substitute mocks or successful CI for these artifacts.
